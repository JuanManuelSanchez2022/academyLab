ACADEMYLAB
Indicaciones técnicas y funcionales para continuar el proyecto
Fecha de auditoría: 2026-11-19

1. IDENTIFICACIÓN DEL PROYECTO

Nombre: academyLab.
Descripción: plataforma local de aprendizaje para perfiles profesionales de IT,
con el primer perfil Cloud / Production Support organizado por rutas, niveles,
cursos, prácticas, evaluaciones y proyectos integradores.
Finalidad: permitir que una persona aprenda conceptos, practique tareas reales
o controladas y conserve un registro verificable de su progreso.
Problema que busca resolver: falta de una vía progresiva y práctica para aprender
Linux, redes, SQL, AWS, Python y procesos de soporte de producción sin depender
de cuentas cloud ni servicios que puedan generar costos.
Público: estudiantes, personas en transición a IT y personal principiante o
intermedio que necesite practicar soporte de producción en un entorno local.

2. VISIÓN Y OBJETIVOS

La plataforma busca desarrollar una ruta profesional progresiva y reutilizable.
El resultado esperado es una plataforma donde el alumno pueda elegir un perfil,
profundidad Básica, Intermedia o Avanzada, completar cursos disponibles y resolver
escenarios integradores. La orientación debe ser práctica: explicar el propósito,
mostrar un ejemplo resuelto, realizar prácticas guiadas e independientes,
verificar resultados, mostrar troubleshooting y aplicar evaluaciones objetivas.

No se pretende presentar una certificación profesional ni un curso completo por
tener una página. Cada competencia debe conservar evidencias y cumplir criterios
verificables. Los AWS simulados se mantienen como escenarios sintéticos y las
integraciones reales deben estar expresamente autorizadas.

3. FILOSOFÍA DE DESARROLLO

- Aprendizaje progresivo y por prerrequisitos.
- Práctica antes que colección de preguntas.
- Separación de perfil, ruta, curso reutilizable, nivel, módulo, evaluación,
  competencia, progreso y evidencia.
- Evaluaciones con puntaje calculado por el servidor y feedback específico.
- Ejecución automática cuando la técnica sea segura y reproducible.
- Separación entre interfaz y mecanismos reales de ejecución.
- No simular integraciones, terminales o resultados AWS.
- No otorgar competencias sin intentos y criterios verificables.
- Mantener archivos y laboratorios independientes del servidor principal.
- Priorizar Python estándar, SQLite y localhost.

4. ARQUITECTURA Y TECNOLOGÍAS REALES

Backend principal:
- Python 3.12.
- web/platform_server.py usa ThreadingHTTPServer de la biblioteca estándar.
- Enlace principal: 127.0.0.1:8765.
- API educativa con SQLite y cookies HttpOnly para una sesión anónima local.

LAB 01:
- labs/lab01-aws-production-support/scripts/web_server.py.
- Enlace bajo demanda: 127.0.0.1:8766.
- analizador Python estándar sin Flask, Django o dependencias adicionales.

Frontend:
- HTML y CSS estáticos dentro de web/.
- JavaScript sin framework.
- assets/platform.css y scripts learning/*.js.
- LAB 01 separado: index.html, styles.css y app.js.

Datos y progreso:
- web/progress_store.py usa sqlite3.
- Base actual: web/data/learning_progress.sqlite3.
- Intentos, puntajes, respuestas, evidencias, competencias y progreso persistidos
  localmente.
- Token de sesión guardado como hash; el navegador recibe una cookie HttpOnly.

Catálogos:
- web/catalog/learning_catalog.json: perfiles, rutas, niveles, cursos, estados,
  competencias y dependencias.
- web/catalog/basic_courses.json: cursos de práctica disponibles.
- web/catalog/linux_basic.json: módulos, prácticas y evaluaciones Linux.

Linux:
- web/linux_runtime.py usa WSL y Ubuntu-24.04.
- Solo ejecuta identificadores allowlisted y scripts fijos.
- El navegador no puede enviar comandos libres.
- Los ejercicios usan directorios aislados bajo $HOME/academyLab del usuario Ubuntu.

Pruebas:
- unittest en web/tests/.
- Pruebas del LAB 01 en labs/lab01-aws-production-support/scripts/run_tests.py.

Dependencias externas:
- Ninguna dependencia Python externa obligatoria.
- Python 3.12 o superior. Los .bat lo buscan con buscar_python.bat (ACADEMYLAB_PYTHON,
  py -3.12 o python del PATH); los servidores usan el intérprete que los ejecuta.
- WSL 2 y Ubuntu 24.04 son requeridos por Linux real.
- Repositorio Git publicado en github.com/JuanManuelSanchez2022/academyLab (rama main).

7. TRABAJO REALIZADO

El LAB 01 procesa archivos de operaciones, eventos y estados. Diferencia eventos
parseados de operaciones únicas y genera conteos por estado. Detecta ERROR,
PENDIENTE y líneas inválidas. Produce evidencias JSON en la carpeta evidence/.

El analizador conserva el comportamiento original desde
labs/lab01-aws-production-support/scripts/analizar_logs.py. La interfaz web no
duplica el analizador: llama al mismo script de Python.

El servidor LAB permite:
- / para index.html.
- /styles.css y /app.js.
- /api/health, /api/files, /api/analyze, /api/tests y /api/evidence.

Resultado verificado al auditar:
- run_tests.py: 8 pruebas PASS y 0 FAIL.
- Prueba normal: 10 eventos parseados, 8 operaciones únicas, 0 líneas no
  parseadas, OK=4, ERROR=3 y PENDIENTE=3.
- Evidencias normal.json y multi_event.json se generan sin alterar la evidencia
  original más allá de las pruebas previstas.

Las pruebas web de plataforma dieron 28/28 OK después de incorporar Ubuntu
24.04. Incluyen sesión, rutas, persistencia, prerrequisitos, feedback,
evaluaciones, bloqueo de Linux, rechazo de comandos de navegador y criterio
Linux del proyecto.

Las 14 prácticas Linux allowlisted fueron ejecutadas realmente en Ubuntu
24.04/WSL 2 y dieron PASS en la auditoría. El análisis integrador real de
grep encontró PX-510 y PX-513 como ERROR y PX-511 como PENDIENTE.

No se realizaron operaciones AWS ni modificaciones en recursos reales.

11. CRITERIOS DE DESARROLLO

- No romper el servidor principal ni el LAB 01.
- No duplicar cursos, módulos o analizadores.
- Mantener el catálogo separado del código que ejecuta actividades.
- No aceptar comandos, rutas o puntajes enviados por el navegador.
- Mantener 127.0.0.1 salvo cambio explícito y autorizado.
- Ejecutar pruebas antes de declarar una funcionalidad terminada.
- Actualizar documentación y estado real en el mismo cambio.
- No escribir métricas ficticias en JavaScript.
- No ejecutar recursos AWS ni generar costos sin autorización.
- No publicar credenciales, bases personales o archivos locales.
- Usar datos sintéticos por defecto.
- Preservar el progreso y las evidencias existentes.

12. CÓMO CONTINUAR

Instalar/usar:
- Windows 10/11, Python 3.12, WSL 2 y Ubuntu 24.04.
- Doble clic en labs\lab01-aws-production-support\iniciar_web.bat.
- Abrir http://127.0.0.1:8765.
- Detener con labs\lab01-aws-production-support\detener_web.bat.

Desarrollo:
1. Ejecutar python -m unittest discover -s web\tests -v.
2. Ejecutar labs\lab01-...\scripts\run_tests.py.
3. Mantener el LAB bajo demanda y no mezclar su servidor con el principal.
4. Modificar el catálogo y learning_service.py de forma coordinada.
5. Agregar pruebas antes de ampliar un curso o criterio.
6. Revisar docs/INSTRUCTIVO_FUNCIONAMIENTO.txt y docs/especificacion-evaluaciones.md.

Git:
- El repositorio oficial es github.com/JuanManuelSanchez2022/academyLab (rama main).
- Publicar requiere permiso de escritura en ese repositorio o un fork con pull request.
- No crear visibilidad pública ni subir datos personales sin confirmar el destino.
